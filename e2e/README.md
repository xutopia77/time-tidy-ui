## 🎯 注释特点

### 1. **层次分明**
```
文件级别注释
  ├── 类/模块级别注释
  │   ├── 属性/元素注释
  │   └── 方法/函数注释
  │       ├── 参数说明
  │       ├── 返回值说明
  │       ├── 使用示例
  │       └── 注意事项
```

### 2. **内容全面**
- **功能说明**：清晰描述代码的功能
- **参数说明**：详细说明每个参数的含义和类型
- **返回值说明**：说明返回值的类型和内容
- **使用示例**：提供实际的使用示例代码
- **注意事项**：说明使用时需要注意的问题
- **最佳实践**：提供最佳实践建议

### 3. **格式规范**
- 使用JSDoc标准的注释格式
- 使用`@param`、`@returns`、`@example`等标签
- 中文注释，便于理解和维护
- 代码示例使用Markdown代码块

## 🔍 注释示例

### 文件级别注释示例
```typescript
/**
 * API辅助工具类
 * 
 * 本文件提供了一组用于直接调用后端API的辅助方法，主要用于：
 * 1. 测试数据准备：在测试开始前创建必要的测试数据
 * 2. 测试数据清理：在测试结束后删除测试数据
 * 3. 测试结果验证：通过API验证UI操作的结果
 * 
 * 优势：
 * - 比UI操作更快，提高测试执行速度
 * - 不依赖UI实现，更加稳定可靠
 * - 可以直接操作数据，便于测试隔离
 */
```

### 方法级别注释示例
```typescript
/**
 * 创建标签
 * 
 * 通过API创建一个新的标签，比UI操作更快更可靠
 * 
 * @param name - 标签名称，建议使用唯一标识（如时间戳）避免冲突
 * @param color - 标签颜色，十六进制格式，默认为红色 '#FF0000'
 * @returns Promise<any> - API响应数据，包含创建结果
 * 
 * @example
 * // 创建红色标签
 * await api.createTag('important', '#FF0000')
 * 
 * @remarks
 * - id设为0表示创建新标签，后端会自动分配ID
 * - 如果标签名已存在，后端可能会返回错误
 * - 建议在测试中使用 `test-tag-${Date.now()}` 格式确保唯一性
 */
```
